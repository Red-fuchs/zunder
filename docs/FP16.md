# fp16 instead of bf16 (2026-10-30)

Why: M1/M2 emulate bf16 (simdgroup MMA ~1.7x slower than fp16). Mixed bf16 activations x fp16 params promote to fp32 (mlx-swift #420), so ALL floating params are cast together.

## Changes
- `Sources/ZunderCore/Dtype.swift`: `resolveDtype` (`--dtype fp16|bf16|auto`, env `ZUNDER_DTYPE`; auto = fp16 on Apple GPU g13/g14 = M1/M2, else bf16), `castParameters` (mapParameters + update, floating params only; packed U32 untouched). Called in `loadContext` for both load paths.
- Flint (fp16 only): first plain cast gave NaN logits on 3 of 6 prompts. Debug (`ZUNDER_ACTDBG=1`): residual stays <= 61, but layer 45 routed experts overflow (post-norm input max 2720 -> silu(gate)*up > 65504). Fix: `FlintMoE.experts` computes silu(g)*u in fp32, rescales each row to max 1 for down_proj, rescales in fp32 (`ZUNDER_SAFEMOE=0` disables). fp32 residual stream (`ZUNDER_RES32=1`) did NOT help, off by default.
- NaN/inf check: `bench` prints "non-finite logit steps"; `gen` records `nonfinite` and sanitizes JSON.
- sl, sl-pnp, sl-pnp-chargen, sl-pnp-itemtest: `Sources/SLCore/Dtype.swift` + one line in `LM.ensureLoaded`; default fp16, `SL_DTYPE=bf16` reverts.

Single runs on a shared machine, noise ~ +-3 tok/s. Gains: decode +4-12 %, prefill +10-12 %.

## sl (Gemma-4 E4B heretic, LFM2.5-2.6B-nothink), `--temp 0 --rng seed:1`, German 4-turn script (--debug stats)
| | bf16 | fp16 |
|---|---|---|
| gemma decode / prefill tok/s | 31.0 / 496 | 33.7 / 676 |
| lfm decode / prefill tok/s | 31.8 / 532 | 37.1 / 573 |
Output: no NaN, coherent German, grammar JSON valid in both. Text diverges from turn 1 (greedy narration, free text, expected; no logit-level check done for sl). Not run on the 4 packages separately: identical code (same md5 LM.swift); all 4 build.
Note: `--model lfm` path in sl points to LFM2.5-2.6B-MLX-bf16 which does not exist on disk; tested with ~/AI-Model/models/LiquidAI/LFM2.5-2.6B-nothink.

## Decisions / open
- Flint: fp16 default (auto on M1). Fallback `--dtype bf16`.
- sl: fp16 default, `SL_DTYPE=bf16` fallback. Gemma sl could have the same outlier-overflow class (layer scalars float16 in Gemma4Text); none observed in this test, longer sessions untested.
- Heretic E4B through zunder not tested (zunder tool format for gemma4 not checked).
- zunder `serve` rewrites ~/.local/state/zunder/pid+port; test server used port 8731.
